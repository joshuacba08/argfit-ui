# ArgFit UI para agentes de IA

El MCP oficial convierte este Storybook y la API pública en contexto estructurado para Claude,
Cursor, Codex, ChatGPT y cualquier cliente compatible. Es de sólo lectura: descubre, recomienda,
genera ejemplos verificables y valida snippets, pero nunca modifica el proyecto consumidor.

<div className="af-doc-callout">
  <strong>Una sola fuente de verdad</strong>

  El catálogo MCP se genera desde las historias, Compodoc, los <code>public-api.ts</code> y los
  tokens. Si una respuesta contradice Storybook o el código público, la fuente debe corregirse
  y el catálogo regenerarse; el JSON generado no se edita manualmente.
</div>

## Conectar

### Desarrollo local

```bash
pnpm mcp
```

### Conectar ArgFit UI a Codex

Desde otro repositorio, registra el paquete publicado como servidor STDIO:

```bash
codex mcp add argfit-ui -- npx -y @argfit-ui/mcp
```

Comprueba la conexión con `codex mcp list`. En Codex CLI o en la app de escritorio también
puedes escribir `/mcp` para ver el servidor y sus herramientas activas. Codex CLI, la extensión
IDE y la app de escritorio comparten la configuración del mismo host.

El repositorio incluye configuraciones portables en `.mcp.json`, `.cursor/mcp.json` y
`.codex/config.toml`. Todas ejecutan el mismo comando desde la raíz, sin rutas personales.

Para instalar el servidor publicado en otro repositorio:

```json
{
  "mcpServers": {
    "argfit-ui": {
      "command": "npx",
      "args": ["-y", "@argfit-ui/mcp"]
    }
  }
}
```

### Clientes remotos

Usa el endpoint Streamable HTTP del portal desplegado:

```text
https://<dominio-de-argfit-ui>/mcp
```

No requiere token en la primera versión y sólo expone conocimiento público de la librería.

## Flujo recomendado

1. Describe la necesidad con `recommend_components` o `search_components`.
2. Confirma el contrato de cada resultado con `get_component`.
3. Obtén una base verificable con `generate_usage`.
4. Aplica los cambios desde el agente anfitrión; el MCP no toca archivos.
5. Ejecuta `validate_usage` sobre el resultado y abre los enlaces de Storybook.
6. Prueba desktop/mobile y dark/light antes de integrar.

Ejemplos útiles para comprobar la conexión:

```text
Busca un selector con búsqueda y carga por scroll.
Compón una pantalla de login y onboarding.
Valida este template y reemplaza cualquier PrimeNG directo.
```

## Seguridad y privacidad

<ul>
  <li>Todas las tools se anuncian como read-only, no destructivas e idempotentes.</li>
  <li>No existe acceso a filesystem, shell, red arbitraria, OAuth ni datos de aplicaciones.</li>
  <li>El endpoint público limita cada request a 64 KiB y no guarda consultas ni snippets.</li>
  <li>Los logs contienen únicamente método, estado, duración y versión del catálogo.</li>
  <li>Cada respuesta identifica la versión; una versión incompatible produce un error explícito.</li>
</ul>
